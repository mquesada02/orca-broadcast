# Research: what decides the title of a tab that `recover` starts, and can it be kept or set again

Ticket: #242. Snapshot taken 2026-11-11, read-only.

Versions checked: Orca CLI 1.4.255 (`orca --version`); Claude Code 2.1.322 (`claude --version`).

Sources (cited as [S1]..[S6]):
- [S1] `orca terminal --help`, `orca terminal create --help`, `orca terminal rename --help`, `orca terminal set-pane-title --help`, `orca terminal list --help`
- [S2] `orca skills get orca-cli` (the Orca CLI guide), the lines on `terminal create --title`, `terminal rename`, `set-pane-title` and `terminals[].title`
- [S3] live `orca terminal list --json` and `--include-visual-layouts` (read-only; 34 terminals joined to their tabs; only field names and counts are recorded, no title text)
- [S4] Claude Code env-var reference, `CLAUDE_CODE_DISABLE_TERMINAL_TITLE` (https://code.claude.com/docs/en/env-vars)
- [S5] Claude Code settings reference, `terminalTitleFromRename` (https://code.claude.com/docs/en/settings-reference); CLI reference, `--name` / `-n` (https://code.claude.com/docs/en/cli-reference)
- [S6] Claude Code "Name your sessions" (https://code.claude.com/docs/en/sessions) and terminal configuration (https://code.claude.com/docs/en/terminal-config)

Also read: the Orca docs pages `cli/reference` and `model/tabs-panes-splits` (https://www.onorca.dev/docs). They list `terminal rename` but say nothing more about title precedence. The code that makes the call today: `startAgent` in `src/orca-adapter.ts` passes `--title` with `<repo>/<worktree> (recovered)` (built in `src/recover-start.ts`).

## Direct answer

1. **Claude Code does set the tab title itself, by default, and `--resume` does not switch that off.** [S4] says the variable disables "automatic terminal title updates based on conversation context", so by default Claude Code updates the title from the conversation. [S5] says "Claude Code sets your terminal tab's title. By default it uses a title it generates from the conversation, and once you give the session a name with `/rename` or `--name`, the tab shows that name instead." [S6] says an unnamed session gets a generated title, "a short summary of your first prompt, written by a background request to the small/fast model". This matches the observation of several tabs showing a title from an old prompt: a resumed session already has a generated title (or a name) from its first prompt. **Unverified:** whether Claude Code writes the title again right after `--resume` or only at the next prompt, and by which escape sequence; the docs name no sequence for the title (they name OSC 8 and OSC 7501 for other features only). Running `claude` was not allowed.
2. **Does Orca show Claude's title instead of `--title`?** Orca's own text says it can: "`terminals[].title` may be the tab title or the running program's own title, which agents repaint constantly, so never match on it to re-find a terminal." [S2] **Unverified:** the rule that picks the shown title. No Orca text states whether a custom tab title beats a program title. `terminal rename --help` says only that omitting `--title` resets "to the auto-generated title" [S1], which implies a custom title and an automatic one are kept apart.
3. **`terminal list --json` returns a `title` per terminal, but it is not a reliable "title the user sees".** Each row has `title` (a string) and, for some, `paneTitle`; the tab title is also in `visualLayouts[].root.tabs[].title` (a separate string per tab), and pane titles in `tabs[].panes[].title`. [S3] In the snapshot, 13 of 34 terminals had `terminals[].title` equal to their tab's `visualLayouts` title; the others differed. 4 rows had a `paneTitle`. The guide says `terminal create --title` and `terminal rename` set the tab title that "`terminal list` reports under `visualLayouts`", and `set-pane-title` is reported as `terminals[].paneTitle` [S2]. So the **custom tab title is the `visualLayouts` one**; `terminals[].title` is unstable. Titles in the live data had no fixed shape and Claude tabs can carry prompt text, so they must not be logged.
4. **Rename exists.** `orca terminal rename --terminal <handle> --title <text>` "Set[s] or clear[s] the title of a terminal tab"; omit `--title` or pass an empty string to reset to the auto-generated title. [S1] `orca terminal set-pane-title --terminal <handle> --title <text>` does the same for one pane (it "Requires the running Orca desktop") [S1]. A chat tab has no terminal handle and uses `chat rename` instead [S2] (not relevant to `claude --resume` in a terminal). **Does a rename survive a later program title?** Not documented. Unverified (no real tab may be renamed to test it).
5. **Claude Code's title can be turned off by a variable that `recover` can type.** [S4] `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1` stops automatic terminal title updates, and it "also skips the background small/fast-model request that generates a session title, and turns off status reports to your terminal". [S5] The setting `terminalTitleFromRename: false` only stops `/rename` and `--name` from changing the tab title; Claude Code still generates its own title, so it does not solve this problem. [S5] says to use the variable to stop Claude Code from updating the terminal title at all. Cost of the variable: it also skips the generated session title that [S6] says works as a `--resume` handle for unnamed sessions. Recover resumes by session id, not by title, so recover itself is not affected; the effect on the later `/resume` picker for that session is unverified.

## What roster save should store, and how recover can restore it

Inference from the sources above; nothing here was run against a real tab.

1. **What to store.** The custom tab title, read from `terminal list --json --include-visual-layouts`, `visualLayouts[].root.tabs[].title` for the agent's `tabId`. Do not store `terminals[].title`: it can be the program's own title, which [S2] says not to rely on, and it can hold private prompt text. Unverified: whether the layout title is empty or absent for a tab with no custom title. If it is, absent means "nothing to restore". If it is not, the roster cannot tell a custom title from an automatic one and should store nothing rather than copy a prompt.
2. **How to restore.** Keep `terminal create --title` as today (the `<repo>/<worktree> (recovered)` label, or the stored custom title if present). Then make it stick:
   - Option A, remove the writer: type `env -u CLAUDE_CODE_RESUME_INTERRUPTED_TURN CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1 claude --resume <id>` so Claude Code never writes a title. This is the only option backed by the docs [S4]. Cost: no generated title for that session, and no status reports to the terminal.
   - Option B, rename after start: `terminal rename --terminal <handle> --title <stored>` once the receipt returns the handle. It works only if a custom title beats the program's title, which is unverified; if it does not, Claude's next update overwrites it.
   - A plus B is the most robust: A removes the writer, B sets the value. Only A is proven by documentation.
3. **Verification still needed (needs a throwaway tab the owner creates).** Create a tab with `--title`, run `claude --resume`, and read `visualLayouts` and `terminals[].title` before and after the first prompt; then rename and repeat. This settles the unverified points in answers 1, 2 and 4.
